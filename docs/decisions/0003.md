# 0003: The app grows into a site of three parts on our own design system

## Decision

- The app becomes a site of three parts: the landing page, "Learn Piano" and "Just Play Piano".
- "Just Play Piano" is the player that exists today. "Learn Piano" is a guided course that plays like
  a game, by the rules of [docs/curriculum.md](../curriculum.md).
- Every page of every part is built from one set of tokens and components, by the rules of
  [docs/site-design.md](../site-design.md).
- The tokens and components are our own code, in plain TypeScript and CSS. No UI framework, router or
  i18n package joins, so three.js stays the only runtime dependency.
- A component is a function that returns an element. A component that changes on its own takes a
  signal, our own small reactive value.
- The font is Plus Jakarta Sans and the icons are a subset of Lucide. Both are self-hosted, so the site
  works offline.
- A test fails on a flaw a person can see: overlap, clipped text, low contrast, a small touch target or
  a layout shift. No test compares pixels.

## Why

The user wants a learning site with a premium look and no visible flaw: no flicker, no overlap and no
misalignment. A look like that holds only when every page draws from one scale. A page that sets its
own colour or size drifts, and nothing notices.

A framework would bring its own components, but it would break the rule of one runtime dependency. Our
own components cost more code, and they keep the bundle small and the app fully ours.

Pixel snapshots differ between systems and fonts, so they fail without a flaw. Measuring the flaws
themselves fails only on a real one, on every system.

## Consequences

- The design system is built and shown on a gallery page before any page uses it.
- The player keeps its look until it moves into the site, and then adopts the components.
- Every page fits the longest language, so the layout checks also run in German.
- Each stylesheet of the site sits in a cascade layer, so a page never fights a component's selector.

## Rejected

- **A UI framework such as React, Svelte or Lit:** a second runtime dependency, and a bundle the
  landing page pays for on its first load.
- **A CSS framework such as Tailwind:** a build dependency and a vocabulary of its own, while the
  tokens already name every value.
- **Pixel snapshot tests:** they differ between systems and fail without a flaw.
- **The system font stack:** it looks different on every system, so the layout checks would measure a
  different page on each.
