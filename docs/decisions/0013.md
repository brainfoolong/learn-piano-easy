# 0013: The mascot's hand is a rigged MakeHuman model that a solver poses on the keys

## Decision

- A lesson shows a movement of the hand with the mascot's hand in the 3D scene, posed live.
- The hand is MakeHuman's CC0 base mesh, rig and weights. `bun tools/hand-model.ts` builds it in
  Blender with MakeHuman's MPFB extension, whose GPL code never ships.
- The built `public/models/hand.glb` is committed, so the app, CI and every session load it without
  Blender.
- The hand is faceted low-poly, in one honey-orange tone with white nails, within 64 KB.
- One right hand ships. A left hand is the same model mirrored.
- A solver in `src/render/hand/hand-rig.ts` bends each digit so its pad meets any point on any key.

## Why

A highlighted key shows which key to play, never how the hand gets there. A thumb passing under or a
hand moving to a new position needs a hand the learner can watch.

A rigged model in the scene follows any fingering of any song, at any tempo and from any view. It
costs one small file and a few bone updates per frame. MakeHuman's hand was made and rigged by artists,
with a bone for each phalanx. Its license, CC0, lets the project ship it and change it freely.

## Consequences

- Blender is needed only to change the model, never to run or test the app.
- Every visitor downloads the hand once with the app shell, which the byte budget bounds.
- The runtime holds no measurements of the model. The model carries them as marker bones.

## Rejected

- **Generated video of a hand:** the video model could not keep the fingering exact. A video also
  fits one song at one tempo from one view, and would weigh far more than the model.
- **A hand built from three.js primitives in code:** it looked wrong, and every joint needed its own
  tuning by hand.
- **A smooth, subdivided hand:** the faceted look was chosen for the mascot. A smooth hand also needs
  normals, which the faceted one does without. `--smooth` still builds one.
