# 0001: Playwright runs the end-to-end tests

## Decision

- End-to-end tests use Playwright Test, pinned at an exact version as a development dependency.
- They live in `e2e/` as `*.e2e.ts`, so `bun test` never picks them up.
- They run in Chromium against a production build, service worker included, served by `tools/dev.ts`.
- The build goes into its own folder under `.agent-tmp/`, never `dist/`.
- `looper verify` runs them as its `e2e` step whenever the app's source, static files or build change.
- A small reporter writes `(pass) <name>` per passing test, the line looper reads.
- The suite runs one browser at a time.
- CI runs them inside Playwright's Docker image, tagged with the pinned version. `tools/ci.test.ts`
  fails when the tag and the pin differ.
- `bun run e2e:docker` runs them locally in the same image. `bun run e2e` and `looper verify` run them
  natively.

## Why

The unit tests run in Bun without a DOM, WebGL, a service worker or Web Audio. The shell, the panels, the
scene and offline start were not checked in a browser. The user chose Playwright for that.

Playwright drives a real Chromium, works offline through `context.setOffline`, and runs the same on
Windows and in CI. It never ships in the app, so three.js stays the only runtime dependency.

## Consequences

- A contributor installs Chromium once with `bun run e2e:install`, or uses Docker instead.
- CI downloads no browser and installs no system libraries. Its image carries both.
- The image has no `unzip` for `setup-bun`, so Bun comes from npm there, at the pinned version.
- A Playwright bump changes `package.json` and the image tag in `ci.yml` in one commit.
- A change the learner can see or do comes with an end-to-end test.
- Headless Chromium draws WebGL in software. On Windows, parallel pages starved each other past the load
  timeout. In the image, four workers took longer than one, so the suite is serial everywhere.

## Rejected

- **Our own driver over the DevTools protocol:** a large tool to write and keep, for no gain to the app.
- **The `playwright` library inside `bun test`:** it loses Playwright's web server, traces and per-test
  browser contexts.
- **Docker for `looper verify` too:** it would need Docker running for every gate, and the native run
  is faster. The image stays one command away.
- **Installing the browser in CI with `--with-deps`:** a download and an apt install on every run.
- **Firefox and WebKit as well:** each adds a download and a run, for an app that targets current
  browsers. One can be added later as another project in the config.
