# 0005: The learner's progress stays on the device, as an event log

## Decision

- The progress of *Learn Piano* is kept in the browser's IndexedDB, on the learner's device. No account
  and no server exist.
- The progress is a log of events. Each finished step and each finished lesson appends one event, and
  an event is never changed or removed.
- XP, stars, levels and streaks are computed from the log on every read. No running total is stored.
- Each event carries the format version it was written in. A newer build migrates an older event, and
  each migration has a test.
- A write counts only once its IndexedDB transaction completes. A failed write leaves the last state
  as it was.
- A backup is one JSON file of the whole log. Importing one merges by event id, so it never removes
  progress.

## Why

The site is free, private and offline. A server would cost money every month, would hold personal
data, and would fail without a network. Progress on the device costs nothing and works on a plane.

A running total breaks for good when one bug adds it up wrong. A log keeps every fact the learner
earned, so a bug in a total is fixed by a new build, and nobody loses work.

## Consequences

- Progress does not follow the learner to another device, except by a backup they move themselves.
- Clearing the browser's site data clears the progress. The settings offer the backup for that reason.
- The log grows with every lesson, which costs a few kilobytes a year.
- The store's logic runs on a small backend interface, so its tests use a memory backend.

## Rejected

- **An account with a server:** it costs money, holds personal data, and breaks the offline rule.
- **`localStorage`:** it writes with no transaction, so a failed write can leave half a state. It also
  holds only a few megabytes.
- **One stored object of totals:** a wrong sum is kept for ever, and a migration has nothing to rebuild
  it from.
