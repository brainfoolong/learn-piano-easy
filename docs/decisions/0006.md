# 0006: The end-to-end tests draw WebGL on the GPU and run in parallel on Windows

## Decision

- On Windows, Chromium draws WebGL on the GPU through Direct3D, with `--use-angle=d3d11`.
- On Windows, four browsers run at once, and any test may run on any worker.
- Elsewhere, such as in CI's image, Chromium draws in software and one browser runs at a time.
- A test that walks the whole course is a test per world, grouped by `test.describe` under one name.
- The pass reporter writes a group's name once every test in it has passed, so a check still names one test.

This replaces the serial rule of decision 0001 on Windows.

## Why

The suite took about 30 minutes, and `looper verify` waited on all of it at every gate.
Software WebGL made each frame of the 3D scene cost about 200 ms. On the GPU, the player and scene tests
ran 3.3 times faster. With four workers on the GPU, the whole suite took 8.4 minutes.

Parallel pages starved each other only because software WebGL used every core. The GPU frees them.

The two course walks were single tests of 6 and 13 minutes, which no worker count shortens. A test per
world lets the workers share them.

## Consequences

- A Windows machine without a GPU falls back to software WebGL. Run it with `--workers 1` there.
- A test may not rely on the state another test left, since it may run first or on another worker.
- A new world adds a test to each course walk with no new code.
- CI keeps its serial software run, which is slower but matches its image.

## Rejected

- **More workers in CI's image:** decision 0001 measured four workers there slower than one.
- **Fewer combinations in the layout checks:** it would cut coverage, while parallel workers cut the
  time without that loss.
- **The GPU everywhere:** CI's runners and Playwright's image have no GPU to draw on.
